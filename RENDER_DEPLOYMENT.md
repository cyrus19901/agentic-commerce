# Render Deployment

The backend runs as a Docker web service on Render, connected to an existing Render PostgreSQL database.

---

## Prerequisites

- `main` branch is already deployed on Render as a Docker web service
- You have an existing Render PostgreSQL database
- You have the internal `DATABASE_URL` connection string from the Render dashboard

---

## Deploying a New Branch

### 1. Merge to main

Create a PR from your feature branch to `main` and merge it. Render will automatically redeploy on push to `main` if auto-deploy is enabled.

To check: Render dashboard → your service → **Settings** → **Build & Deploy** → confirm branch is `main` and auto-deploy is `Yes`.

### 2. Manual deploy (if auto-deploy is off)

Render dashboard → your service → **Manual Deploy** → **Deploy latest commit**.

## First-Time Environment Variables

These must be set in Render dashboard → **Environment** before the first deploy. Values marked `sync: false` in `render.yaml` are never committed — you set them once in the dashboard.

| Variable | Where to get it |
|---|---|
| `DATABASE_URL` | Render dashboard → your PostgreSQL db → **Internal Database URL** |
| `WALLET_ENCRYPTION_KEY` | Generate: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `JWT_SECRET` | Auto-generated by Render (`generateValue: true` in render.yaml) |
| `OPENAI_API_KEY` | platform.openai.com |
| `FIRECRAWL_API_KEY` | firecrawl.dev |
| `FIRECRAWL_AGENT_PRIVATE_KEY` | 0x-prefixed hex key for the Base L2 agent wallet |
| `ZYTE_API_KEY` | zyte.com |
| `STRIPE_SECRET_KEY` | dashboard.stripe.com (optional) |
| `SOLANA_RPC_MAINNET` | Alchemy / Helius RPC endpoint (optional) |

Everything else (`PORT`, `NODE_ENV`, `ALLOWED_ORIGINS`, etc.) is already set in `render.yaml`.

## Database Migrations

Migrations run **automatically on every deploy** via `scripts/docker-entrypoint.sh`:

```sh
npm run db:migrate --workspace=@agentic-commerce/database
```

No manual steps needed. Check Render logs for:
```
✓ Migrations complete
✓ Starting server on port 3001...
```

## Troubleshooting

**Deploy fails at build**
- Check Render build logs for TypeScript errors
- Ensure `packages/shared` and `packages/database` build before other packages (handled by `Dockerfile`)

**`DATABASE_URL is required` on startup**
- Set `DATABASE_URL` in Render → Environment → add environment variable

**Migrations fail**
- Confirm `DATABASE_URL` points to the correct Render PostgreSQL instance (use the **Internal** URL for same-region services)
- Check the database is not sleeping (Render free-tier PostgreSQL suspends after 90 days of inactivity)

**Port issues / health check failing**
- Service must expose port `3001`. Render detects the port automatically from `EXPOSE 3001` in the Dockerfile.
